## 1. Phase 0 — the five answers

**Where `stackfulBackend` is read.** Thirteen sites; the ones that matter are four:

| site | what it decides |
|---|---|
| `src/compiler.ts:408` | the `Options` field — **the default**, was `"continuation"` |
| `src/compiler.ts:980` | `fiberBackendActive` — which shell to prepare |
| `src/transforms.ts:387` | chooses `StackfulAsyncTransform` vs `AsyncLowerTransform` |
| `src/async/stack.ts:484` | chooses the fiber drive body vs the promise one |

`cli/index.js:364` only forwards the parsed value. **Three of those four compared the literal
`"fiber"`**, which is §4's first finding.

**What the compiler already reads for config.** Not nothing — the seat's claim was wrong.
`cli/index.js:251` resolves `opts.config || "asconfig.json"`, and `:294`/`:300` merge
`targets.<name>.options` then `options`, before `optionsUtil.addDefaults` at `:324`. That is
**flag > config > default**, already implemented.

**And this tree already uses it**: `tension-framework/build/session.asconfig.json` is
generated by `scripts/gen-session.mjs` and passed by five scripts. So the round added **no
new config mechanism**.

**Call sites.** 0 examples pass a backend flag (so all inherit the default);
`scripts/build-test-programs.mjs` has two flag lists that did; 14 TensionScript test
harnesses passed `--enable stack-switching` and read continuation into it; 4 showcases did
the same; 1 (`coreloop.js`) passed neither and read the default.

**The artifact's existing metadata.** `tension.stackful-backend` — **already there**, written
only for fiber, absence meaning continuation. No producers section, no feature section.

**Does a fiber artifact declare its features?** No — and neither did a continuation one.
`WebAssembly.Module.imports/exports` say what a module *offers*; nothing said what it
*needs*. That is the gap `requires` closes, and without it the host can check nothing.

## 2. Phase A — the default, and the config that already existed

`auto` is the default and resolves to fiber on every target. Precedence is unchanged from
what the compiler already did; three runs of one guest:

| where the value came from | artifact |
|---|---|
| nothing | `backend=fiber`, **313 B** |
| `asconfig.json` → `continuation` | `backend=continuation`, **23,618 B** |
| config **and** `--stackful-backend=fiber` | `backend=fiber`, **313 B** — flag wins |

Choosing `continuation` enables `--enable stack-switching` itself (§1.3).

### Byte identity (gate 3)

```
async-main-promise     1bad58703ee111e2  identical  14,459 B
spawn-join             d22880711a7cabff  identical  29,793 B
async-before-await     3d200da65045cf1f  identical 152,821 B
```

No flag and `--stackful-backend=fiber` produce the **same bytes** — the default is the same
lowering, which is the gate's question.

### The divergence that made this necessary

The first attempt at byte identity **failed**: `auto` gave 23,865 B and `fiber` 14,437 B, and
**both declared `backend=fiber`**. Cause: the shell read `fiberBackendActive` (with `auto`)
while `transforms.ts` and `async/stack.ts` still compared the literal `"fiber"` — so the
shell was fiber and the drive body was the promise path. One accessor,
`Options.fiberBackendSelected`, is now read by all three. This is the round's own lesson in
miniature: two spellings of one question drift the moment a third value exists.

## 3. Phase B — the declaration, and the refusal

`tension.requires`, quoted from real artifacts (one per lowering):

```
backend=continuation          backend=fiber                backend=promise
target=linux-only             target=portable              target=portable
features=stack-switching,     features=shared-memory       features=shared-memory
         shared-memory
```

Three `key=value` lines, no JSON: the writer is the compiler and the reader is Rust with no
serde in the runtime. Only features a host must **configure** are listed.

**The host checks it before instantiation**, and refuses with both facts, exit 2:

```
tension-core: this guest was built for the `continuation` backend and this executor is the
`fiber` backend — refusing by name, nothing was run
```

```
tension-core: this guest's `tension.requires` says backend `continuation` but its
`tension.stackful-backend` says `fiber` — refusing by name, the artifact is inconsistent and
nothing was run
```

The second is new: the two sections are written by one build, so a disagreement means the
artifact is not one the compiler wrote.

**What the host did before this round** (gate 5), measured:

```
$ wasmtime run build/main-policy.wasm
Error: failed to parse WebAssembly module
Caused by:
    cannot define continuation types when stack switching is disabled (at offset 0x26)
```

A byte offset, and neither side named.

Nine unit tests in `fiber::tests` pin the parser and the refusal: portable accepted on any
platform, linux-only refused off Linux, `shared-memory` refusable, an unknown value never
folded into a default, and **a trailing space must not disable the check** — which it did,
until measured (§4).

## 4. Three things the work found that the brief did not anticipate

**1. The promise lowering is not replaceable.** `auto` → fiber broke
`tests/async/runtime.js`: its probe is a **library module** — an `await`, no exported `main`
— and a stackful shell refuses it because there is no root to resume. The promise lowering is
the only one that compiles it. So `promise` is a named third value (and `Backend::Promise` on
the host), never selected by `auto`.

**2. The shell resumed only a function called `main`.** Making `auto` mean fiber failed to
build **every example in Tension**: 0 of 17 export `main`, they export `_start_game`. The
refusal's own words say what it wants — *a root to resume*, not a name — so
`compileModuleExports` now records the `--exportStart` entry as a fallback root. Without this,
gate 8 was impossible.

**3. `fiber-runner`'s "continuation guest" was a promise artifact.** It loaded
`wake-on-worker.wasm`, built with no backend flag, which read as continuation only because the
old encoding was "no section ⇒ continuation". Writing the section made the mislabel visible
and the test failed — correctly. It now loads `suspend-serve`.

**And a parser bug of mine**: an untrimmed `key=value` parsed as an unknown target class,
`Requires::of` answered `None`, and the host **skipped the check entirely**. A declaration
that fails to parse must never become a module waved through.

## 7. What the tree contradicted in this brief

- **"What does the compiler read today that could hold config? The seat's claim is *nothing*."**
  It reads `asconfig.json` (`cli/index.js:251`), and this tree already ships one. No new
  mechanism was invented — that is a smaller round than the brief assumed.
- **"Emit a `requires` block"** — `tension.stackful-backend` already existed, so this is a
  second section beside it, not a new place. Stated so the two are not confused.
- **`auto`, `fiber`, `continuation` are not enough.** A fourth value, `promise`, had to be
  named or library modules stop compiling.
- **A default is not just a value.** It is also every place that encoded the old default by
  omission: three literal comparisons, 14 harnesses, 4 showcases, 1 suite, 1 host test.
