# tension-2d — the 2D renderer

`tension-2d` is the module that puts SDL_GPU's sprite pipeline behind the wasm
import module `tension::2d`. It owns a GPU device, an offscreen canvas, a
pipeline table and a texture table; it owns **no regions**, publishes nothing into
the arena, and keeps no state the guest cannot recover from its own records.

**It is in core.** Until Pass B of the merge it was a capability DSO — an
`adapter.cpp` edge and a `render.cpp` body talking across the adapter ABI. The
renderer now lives in `tension-core/src/render2d/`, and the ten verbs are
`func_wrap`s in `tension-core/src/main.rs`. The C++ it came from is kept
unchanged in `tension-2d/reference/` for one pass, so a parity failure has a
known-good source to read beside the Rust.

This page states what it is, what it refuses, and where it disagrees with the
architecture. It is derived from code. Every claim carries a `file:line`; a bare
filename means a file under `tension-core/src/render2d/`, except `reference/…`,
which names the pre-port C++.

> **Citations to design notes.** `tension-ogre/DESIGN.md` and
> `tension-2d/DESIGN.md` were deleted in pass 7. Every claim these pages drew
> from them is preserved here; a `DESIGN.md:` citation below is a historical
> reference to a file no longer in the tree, kept so the provenance of a
> sentence stays legible.

## 1. What this module is

An in-core module of `tension-core`, registered by `link_2d`
(`tension-core/src/main.rs`) when the `render2d-core` feature is on — which it
is by default since Pass B. It defines the wasm module `tension::2d`: ten
imports, all `i32`. Everything the guest sends arrives as bytes in guest memory
and is copied out before it is used.

**The bisect escape hatch.** With `render2d-core` off (`cargo build
--no-default-features`, or `TENSION_RENDER2D=cpp` in `scripts/build-native.mjs`)
the imports come from a DSO built out of `tension-2d/reference/`
(`node scripts/build-2d.mjs --cpp`). That path exists so a bisect can answer "is
this the port?" without rebuilding anything else, and it is held to the same wire
by `tension-core/tests/2d_surface.rs`. Pass C removes it.

## 2. The ten verbs

Registered in `link_2d` (`main.rs`), module `tension::2d`. Signatures and guest
wrappers are `docs/abi/guest.md`; this table is what each does and how it
refuses.

| # | verb | id | signature | what it does | refuses |
|---|---|---|---|---|---|
| 1 | `open` | 1 | `(w, h, flags) -> handle` | device, target, session; the host's window when bit 0 is set | `-EINVAL` size/flags, `-EBUSY` already open, `-ENODEV` no device or window, `-ENOMEM` target, `-EIO` device creation |
| 2 | `close` | 2 | `(handle) -> i32` | release every texture, pipeline, buffer, target, device — and `open` again for a new canvas. A handle left open is released when the store drops | `-EINVAL` unknown handle |
| 3 | `set_pipeline` | 3 | `(handle, blob_ptr, blob_len) -> pipe_id` | preset by id, or a graph blob | `-EINVAL` handle/empty blob, `-ENOENT` preset outside 1..99, `-ENOSYS` a preset this build does not carry or a graph the compiler refuses, `-ENOSPC` table full, `-EIO` pipeline creation |
| 4 | `shader_compile_raw` | 4 | `(handle, vs, vs_len, fs, fs_len) -> pipe_id` | raw GLSL in | `-ENOSYS` — no translator behind the verb |
| 5 | `submit` | 5 | `(handle, pipe_id, hdr_ptr, z_bucket) -> count` | copy a record array into a bucket | `-EINVAL` handle/header/stride, `-ENOENT` pipe, `-ENOSPC` stager full |
| 6 | `present` | 6 | `(handle) -> i32` | sort, draw one call per bucket, blit or read back | `-EINVAL` handle, `-ENODEV` no device, `-EIO` submit failed, `-ECANCELED` window closed |
| 7 | `texture_load` | 7 | `(handle, src, len, format) -> texture_id` | decode IWI and upload | `-EINVAL` malformed container, `-ENOSYS` unknown format, `-ENODEV`, `-ENOMEM` |
| 8 | `info` | 8 | `(handle, ptr, cap) -> bytes` | 24-byte snapshot: limits, canvas size | `-EINVAL`, `-ENOSPC`, `-ENODEV` — the one verb that answers `-ENODEV` for a missing canvas |
| 9 | `screenshot` | 9 | `(handle, ptr, cap) -> bytes` | RGBA8 readback of the last frame | `-EINVAL`, `-ENODEV` nothing presented, `-ENOSPC` short buffer, `-EIO` download |
| 10 | `set_texture` | 10 | `(handle, pipe_id, slot, texture_id) -> i32` | bind a texture to one page of a pipeline's array | `-EINVAL` slot/dimension, `-ENOENT` pipe/texture, `-ENOMEM`, `-EIO` |

**The verbs are not deferrable.** None carries the `DEFERRABLE` flag: `submit`
could be, and deliberately is not, because its answer is a count the caller uses
to decide whether to split a bucket and a deferred call cannot answer. The
`REENTRANT_READONLY` flag that `info` carried in the DSO has no in-core analogue
— a `func_wrap` is re-entered through the wasm stack, not through an import
table, and `info` reads only `Render2dState` fields that no other verb mutates
while it runs.

**`submit` is one copy for the whole array**, not one per record. The shim reads
the 12-byte header and then `records_count × record_stride` bytes in a single
`guest_bytes` call (`main.rs`); a 4096-record bucket is one pass over guest
memory, where per-record reads would be 4096.

The surface is pinned twice. `tension-core/tests/2d_surface.rs` pins the DSO's
registration table (bisect path) — ten verbs, their ids, `publish`/`apply` NULL,
and that `post_control`/`host_surface` are never called. On the in-core side the
pin is instantiation: a guest that imports the ten verbs is linked against
exactly those definitions or the wasm linker refuses the module, and every 2D
example does it. Behavioural pinning is §7.

**The guest SDK wraps this table.** `tension-framework/assembly/2d/verbs.ts`
declares nine of the ten verbs (all but `shader_compile_raw`, which answers
`-ENOSYS` everywhere and which no example calls), and
`tension-framework/assembly/2d/canvas.ts` wraps them as `Canvas` — one object per
open handle, returning the errno unmodified. The wire numbers live beside them in
`2d/constants.ts`, each citing its line of `tension-2d/include/tension_2d.h`.
Both mutable examples (`examples/2d/hello-sprites`, `examples/2d/isometric-framework`)
open a `Canvas` and declare no verb; `examples/2d/isometric` keeps its own
hand-written declarations as the oracle, so a wrapper that lies about the wire is
a diff, not an opinion.

## 3. The window it presents to

**The renderer does not create a window. It claims the host's.**

`open` with `TENSION_2D_OPEN_WINDOWED` asks the host for a window and claims it
for its GPU device:

```rust
let window = HostWindow::new("Tension", width, height)?;   // on demand
device.with_window(window.sdl_window())?;                   // SDL_ClaimWindowForGPUDevice
```

(`device.rs`). The offscreen path — the default, and what every test uses —
creates no window at all.

This is the repair of a contradiction this page used to record. `tension-2d` was
a capability DSO, and `SDL_GPU` has no external-surface API: there was no way to
hand a swapchain-less capability the host's `SDL_Window`, so it made its own and
a `--window` run had two. Moving the renderer into core removed the boundary that
made the workaround necessary.

**The window is created on demand, at the size the renderer declares.** There is
no `--window` to keep in step with `Canvas.open(320, 180)`: the guest asks, the
host makes one 320x180 window, the renderer claims it. `--window <W>x<H>` still
exists for the one case with no renderer at all — `examples/platform-control`,
which drives the control bus and draws nothing — and for test and tooling runs
that want to choose the size before a guest starts.

**One renderer holds the swapchain.** `Render2dState::claim_swapchain` refuses a
second claimant with `-EBUSY` and a message naming the holder, *before*
`SDL_ClaimWindowForGPUDevice` is called. SDL is the backstop, not the mechanism:
`VULKAN_ClaimWindow` (`SDL_gpu_vulkan.c:9940-10012` at release-3.4.18) refuses a
different device cleanly with `"Window already claimed"` and leaves the existing
claim untouched, but its refusal arrives as `-ENODEV` with a string that reads
like "no GPU". Core mediates first so the guest gets a sentence it can act on.

**What is still offscreen-only in practice.** Every 2D test and CI path runs
`SDL_VIDEODRIVER=offscreen`, so the windowed *claim* is exercised by
`tension-core/tests/render2d_open.rs` but the *pixels* a user would see are only
checked on a machine with a conformant Vulkan ICD. See
[`../known-limitations.md`](../known-limitations.md).

## 4. The graph compiler

The deleted `tension-2d/DESIGN.md` said, in its status paragraph: **"What is
not built is §6: the graph compiler. `set_pipeline` accepts the built-in preset
by id and answers `-ENOSYS` for a guest blob."**

The code disagrees, and always did — DESIGN.md's own §14.2 has the correct
account ("Runtime compiler — built, narrowly"), which makes §6's status line
stale *within the same document*.

**What changed in the merge.** In the DSO, `set_pipeline` for a graph blob was a
three-step dance: look the blob's hash up in the artifacts the build had embedded
(`reference/render.cpp`, `set_pipeline_blob`), answer `-ENOSYS` for anything else,
then have `adapter.cpp` call the host's `compile_graph` slot **twice** — once with
null buffers to learn the sizes (`-ENOSPC` carries them), once with real buffers
to transfer the modules — and re-enter the renderer through
`set_pipeline_spirv`.

In core, the compiler is `crate::pipeline::naga_backend` and the renderer is a
function call away. `PipelineCache::blob` (`pipeline.rs`) does parse → validate →
lower → compile → build in one call. The probe, the transfer and
`set_pipeline_spirv` are gone, and so is the reason they existed: two components
that were never actually two processes.

**The ids are unchanged.** A blob whose hash matches `default_2d` still resolves
to pipe 100 and `default_2d_scaled` to 101 — computed from `pipeline_default`'s
own serialization at first use, not transcribed, and pinned by
`tests/render2d_parity.rs`. Anything else compiles and takes an id from 1000 up,
which is the range `tension_2d.h` reserves for runtime-compiled graphs.

**The preset is compiled, not embedded.** The DSO carried `kSpriteVertSpv` and
`kSpriteFragSpv` in a generated C header. In core, preset 1 is compiled from
`crate::pipeline_default::default_graph` at first use and cached for the process.
`scripts/build-2d.mjs` still asserts that the preset's modules and the graph's
are byte-identical — and `tests/render2d_parity.rs` asserts that the *Rust*
compiler's output equals the modules the C++ build left behind, byte for byte.
That is why the preset and the graph still cannot drift: both claims are checked,
one at build time and one at test time.

**What is genuinely not built is `shader_compile_raw`.** Verb 4 answers `-ENOSYS`
because no build has a GLSL → SPIR-V *verb* behind it. In core the machinery
exists — the compiler is right there — but serving it is a new capability, not a
port, and Pass B is a port. The door stays shut and says so.

**Bounds on the claim.** The runtime compiler is proven for graphs whose structure
the GLSL backend already lowers; a graph shape it does not know is a refusal, not
a crash. The narrowing is **[I]**: no test enumerates which shapes the GLSL
backend refuses.

## 5. The rendering path

**Open.** SDL's video subsystem (`device.rs`, `ensure_video`) — refcounted
process-wide, and `dummy` refused by name — then `SDL_CreateGPUDevice(SPIRV)`, the
host window and its claim if asked, then the offscreen target at canvas size, the
1x1 white default array (16 layers), the sampler, and the storage and upload
buffers sized `4096 × 28`.

**Submit.** The 12-byte header plus `records_count × record_stride` bytes are read
in one `guest_bytes` call, the stride is checked against the layout, and the
records are appended to the named bucket (`main.rs`, `Render2dState::submit`). A
bucket holds 4096 across all buckets; a full stager is `-ENOSPC` and the caller
splits.

**Present.** Stable-sort each bucket on `(sort_key, group_id, z)` — the key order
is `record::SORT_KEYS`, rebuilt from the graph's `make_tuple` in
`tests/render2d_parity.rs` so it cannot drift — concatenate the buckets into one
frame array, upload once, and draw one call per bucket with `first_instance`
distinguishing them. Sorting is stable so equal keys keep submission order, which
is what makes a frame reproducible.

**Present to a window.** When a window is claimed, `present` acquires the
swapchain and blits the target into it — a blit rather than a second render pass
because the target and the swapchain may differ in format. A null swapchain is
legal (a minimised window) and the frame is still drawn. The readback path is
unaffected: `screenshot` returns the same frame either way.

**Textures.** `texture_load` decodes IWI (`iwi.rs`): magic `IWI1`, 74-byte
header, interleaved 8-bit RGB/RGBA; planar storage is refused at v1. PNG and JPEG
are `-ENOSYS`, not a guess. A texture uploads to a `SDL_GPUTexture`; `set_texture`
copies it into one layer of a pipeline's array texture of
`TENSION_2D_MAX_ATLAS_PAGES` = 16 layers, so every page of a pipeline shares one
size and a mismatched page is `-EINVAL`.

**Screenshot.** `SDL_DownloadFromGPUTexture` into RGBA8, top-left origin,
non-premultiplied, always `w × h × 4` bytes regardless of what the driver chose
internally (`tension_2d.h:258-267`).

All of this is **[V]** except the pixels of a windowed present, which no test on
this rig can produce (§3, §7).

## 6. Failure modes

The vocabulary is the adapter ABI's, carried over variant for variant
(`error.rs`), with the recorded `-ENODEV` exception all three capability headers
carry (`tension_2d.h:366-381`).

- **`-EINVAL`** — the catch-all: a bad handle, `flags` with an unknown bit, a
  canvas outside 1..16384, a non-zero submit header flag, a stride that disagrees
  with the layout, a slot outside 0..15, a texture whose dimensions disagree with
  the array.
- **`-ENOENT`** — a `pipe_id` or `texture_id` this handle never had; a preset id
  outside `PIPE_PRESET_MIN..MAX`.
- **`-ENODEV`** — no GPU device (no driver, no ICD), the `dummy` video driver, a
  window that could not be created or claimed, a missing canvas (`info`), or
  `screenshot` before anything has been presented. This is the code outside the
  ABI's closed list; the amendment the core owes is one line
  (`tension_2d.h:366-372`).
- **`-ENOSYS`** — a preset this build does not carry, a raw-shader compile, a
  texture container or layout this build does not decode.
- **`-ENOSPC`** — a full stager, a short guest buffer, a full pipeline table (16).
- **`-EIO`** — SDL refused, pipeline creation failed, a decode or download failed.
- **`-ENOMEM`** — target, texture or array allocation failed.
- **`-ECANCELED`** — the windowed handle's window was closed. `present` answers
  it once and then draws nothing more (`tension_2d.h:78-80`).

**The `dummy` driver is refused by name.** `dummy` comes up as a video driver with
no GPU backend, so `SDL_CreateGPUDevice` fails against it with "No supported
SDL_GPU backend found!" — which reads as "this machine has no GPU" when the answer
is "this driver has no GPU". `open` checks the current video driver before any
device is attempted and refuses with a diagnostic that names both the driver and
the one that works. The errno is `-ENODEV`, unchanged: it is the same refusal the
device-creation failure would have produced, reached one step earlier and
reported honestly. Pinned by the `dummy` case in `tests/render2d_open.rs`, which
runs on this rig precisely because it fires before any device exists.

The errno table is **[V]** (each code is a `Render2dError` variant and a test in
`tests/render2d_open.rs`); the claim that every path is reachable is **not yet
proven** — several refusals, notably `-EIO` on pipeline creation, need a driver
that fails.

## 7. Tests

**The unit of proof is three files now, and none of them is a stub core.**

- `tests/render2d_open.rs` — the device, the window claim, the swapchain guard,
  the `dummy` driver, every verb's refusals, and one real frame: an empty
  `present` clears to `(0,0,0,255)` and `screenshot` reads it back, asserted
  pixel by pixel. That is the only pixel assertion that runs without a graphics
  pipeline, and it is why the clear colour, the target format and the readback
  layout are pinned on a rig where nothing else can draw.
- `tests/render2d_parity.rs` — the port's proof, in three parts, each able to run
  or skip on its own. See below.
- the unit tests in `record.rs`, `iwi.rs` and `pipeline.rs` — the record
  comparator (including that a `u8` key at offset 26 is still compared), the IWI
  reader's refusal order, and the blob-to-pipe-id routing.

**The parity harness is the one that matters.** `node scripts/parity-2d.mjs`
builds both backends and runs the test:

1. **Shader bytes.** The Rust compiler's preset and graph modules are compared,
   byte for byte, to the `.spv` files `scripts/build-2d.mjs` produced for the C++
   build. Identical SPIR-V plus identical pipeline state is a stronger statement
   than one frame's diff: it says the draw cannot differ.
2. **Ordering.** `SORT_KEYS` is rebuilt from `default_graph()`'s `make_tuple` and
   compared, so a graph change the comparator did not follow fails here.
3. **The two binaries on one guest.** The same `game.wasm` through a
   `--no-default-features` binary (DSO) and the default one (in core), comparing
   stdout line for line — which for `hello-sprites` includes its own full-frame
   pixel count and ten sampled colours.

**Part 3 is blocked on this rig.** `vkCreateGraphicsPipelines` fails with
`VK_ERROR_OUT_OF_HOST_MEMORY` under Mesa's `dzn`, reproduced by the untouched C++
oracle, so neither backend can build a pipeline and no frame exists to compare.
The harness reports the skip, states the assertion that would run, and
additionally asserts that *both* backends fail at the same verb with the same
errno. On a machine with a conformant ICD the raw-frame comparison is available
too: `TENSION_CORE=<binary> node examples/2d/isometric/test.mjs` prints the
guest's own `FRAME <name> <offset> <hex>` lines, which must be identical between
the two binaries.

**In `npm test`:** the 2D path is covered by `isometric` and `isometric-framework`
(`scripts/test.mjs:239-285`), which build real guests and assert specific pixels,
and by `isometric-art` (`:254-266`). They run against whichever backend the built
`tension-core` carries — in core, by default.

**Not covered by any test on this rig:** the pixels of a windowed present, and any
scenario that needs a graphics pipeline. The suites above need one too; on a
machine without a working ICD they fail rather than skip, which is the policy in
`tests/support/ci.rs`.

## 8. Non-goals

- **The record layout belongs here, and is here.** There is exactly one record
  shape, 28 bytes, and it is the wire (`tension_2d.h:272-290`); there is no
  separate region or table to describe. The guest SDK's view is
  `tension-framework/assembly/2d/types.ts`.
- **`shader_compile_raw`'s translator** — deferred; the door exists in the wire,
  not in the build (`tension_2d.h:143-151`, §4).
- **Window ownership** — done, §3. The window is the host's.
- **PNG/JPEG decoding** — `-ENOSYS`, and not a pending fix. Every shipped texture
  is converted to IWI by the build pipeline; a runtime decoder would need either a
  wider `iwconv` (build-time only) or a capability DSO linking a C library over
  ImageViewer's plugin decoders. Neither is committed.
- **Skeletal 2D, per-frame uniforms beyond `parallax_offset`, Android, an
  alternative-backend vtable** — `DESIGN.md:1279-1299`, still accurate.
- **The adapter ABI, the guest import list, the session contract** —
  `docs/abi/adapter.md`, `docs/abi/guest.md`, `docs/session.md`.

**Licence posture, preserved from the design note.** Everything in the 2D path is
permissive: SDL3 (Zlib), glslang (BSD-3, build-time only — it never reaches the
binary's `DT_NEEDED`), Cranelift (Apache-2.0 with LLVM exception, already
transitive through Wasmtime), ImageViewer (Apache-2.0, not MIT), Tension and
TensionScript (MIT). FreeImage — the one non-permissive dependency — was removed
outright, and `third_party/patches/ogre-no-freeimage-codec.patch` plus the
configure flags (`scripts/bootstrap.mjs:418-419`) are what keep it out. No GPL or
LGPL is in the path. `DESIGN.md:1233-1277` is the long form;
`third_party/README.md:88-107` carries Ogre-Next's half.

## 9. Source index

**Citations are point-in-time.** They go stale when a cited file changes above
them, and no drift gate exists for this page — only the generated `docs/abi/*.md`
are drift-checked. Re-verify a citation before acting on it.

- `tension-2d/include/tension_2d.h` — the guest boundary: ten verbs, the 28-byte
  record, pipe-id ranges, texture formats, refusals. Unchanged by the merge; it
  is the contract, not the ABI.
- `tension-core/src/render2d/device.rs` — SDL_GPU: device, window claim, target,
  buckets, sort, present, readback.
- `tension-core/src/render2d/pipeline.rs` — preset, graph blob, and the one-call
  compile that replaced `compile_graph`.
- `tension-core/src/render2d/record.rs` — the 28-byte record and the graph's
  ordering.
- `tension-core/src/render2d/iwi.rs` — the IWI reader.
- `tension-core/src/render2d/error.rs` — the refusals and their errnos.
- `tension-core/src/main.rs` — `link_2d`: the ten `func_wrap`s and the guest
  memory helpers.
- `tension-2d/reference/` — the pre-port C++, unbuilt, until Pass C.
- `scripts/build-2d.mjs` — the shader pipeline: GLSL → SPIR-V → the `.spv` files
  the parity test compares against. `--cpp` additionally links the bisect DSO.
- `scripts/parity-2d.mjs` — both backends, then the comparison.
- `tension-core/src/pipeline/` — the compiler the renderer calls directly:
  parser, validator, GLSL backend, naga backend, Cranelift comparator.
- `tension-framework/assembly/2d/` — the guest SDK (types, tileset, composite,
  isometric world).
