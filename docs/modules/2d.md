# tension-2d — the 2D capability

`tension-2d` is the shared object that puts SDL_GPU's sprite pipeline behind the
wasm import module `tension::2d`. It owns a GPU device, an offscreen canvas, a
pipeline table and a texture table; it owns **no regions**, publishes nothing into
the arena, and keeps no state the guest cannot recover from its own records. This
page states what it is, what it refuses, where it disagrees with its own design
note, and — in §3 — the one place it contradicts the architecture.

It is derived from code. Every claim carries a `file:line`; a bare filename means
a file under `tension-2d/src/` (`adapter.cpp`, `render.cpp`, `render.h`,
`texture.cpp`). Claims that are design intent rather than behaviour are marked
**[I]**; claims with no test behind them are marked **not yet proven**.

## 1. What this module is

A capability DSO, built as `libtension_2d.so` (`scripts/build-2d.mjs:1-17`),
loaded by `tension-core` through the adapter ABI. It exports `tension_adapter_v1`
and publishes a vtable whose `publish` and `apply` are both `NULL`
(`adapter.cpp:505-516`) — the module owns no arena regions and has no deferrable
verb.

The guest-visible surface is the wasm module `tension::2d`: ten imports, all
`i32`, registered in `link` (`adapter.cpp:451-471`). Everything the guest sends
crosses through `guest_read` inside the call and is copied; the adapter never
holds a guest pointer (`tension_2d.h:36-38`, `render.cpp:37-40`).

**Ten verbs, not nine.** The design note says "registers the nine imports"
(`DESIGN.md:108`, repeated at `:1541`), and the smoke test's header comment still
says "the nine verbs" (`scripts/test-2d.mjs:8`); the tenth, `set_texture`, was
appended later and is last in the table so no existing verb id moved
(`adapter.cpp:463-464`).

**What it owns.** A GPU device, a window only when asked for one, an offscreen
colour target, up to 16 pipelines (`render.cpp:58`), up to 64 textures
(`render.cpp:57`), 8 buckets of 4096 records each (`render.cpp:55-56`), and one
session (capacity 1 — a second `open` is `-EBUSY`).

**What it does not own.** No arena region, no session state, no host window, and
no clock. Time is the guest's (`docs/architecture.md` §1); the only per-frame
input the module takes is whatever a `submit` names.

## 2. The ten verbs

Registered in `adapter.cpp:451-472`, module `tension::2d`. Signatures and guest
wrappers are `docs/abi/guest.md`; this table is what each does and how it
refuses.

| # | verb | id | signature | what it does | refuses |
|---|---|---|---|---|---|
| 1 | `open` | 1 | `(w, h, flags) -> handle` | device, target, session; window when bit 0 is set | `-EINVAL` size/flags, `-EBUSY` already open, `-ENODEV` no device or window, `-ENOMEM` target, `-EIO` device creation (`adapter.cpp:457`, `:117`) |
| 2 | `close` | 2 | `(handle) -> i32` | release every texture, pipeline, buffer, target, device | `-EINVAL` unknown handle (`:458`, `:147`) |
| 3 | `set_pipeline` | 3 | `(handle, blob_ptr, blob_len) -> pipe_id` | preset by id, or a graph blob | `-EINVAL` handle/blob header, `-ENOENT` preset outside 1..9, `-ENOSYS` uncompilable blob, `-ENOSPC` table full, `-EIO` translation (`:459`, `:157`) |
| 4 | `shader_compile_raw` | 4 | `(handle, vs, vs_len, fs, fs_len) -> pipe_id` | raw GLSL in | `-ENOSYS` — no translator in the DSO (`:460`, `:248`) |
| 5 | `submit` | 5 | `(handle, pipe_id, hdr_ptr, z_bucket) -> count` | copy a record array into a bucket | `-EINVAL` handle/header/stride, `-ENOENT` pipe, `-ENOSPC` bucket full (`:461`, `:257`) |
| 6 | `present` | 6 | `(handle) -> i32` | sort, draw one call per bucket, blit or read back | `-EINVAL` handle, `-ENODEV` no device, `-EIO` submit failed, `-ECANCELED` window closed (`:462`, `:302`) |
| 7 | `texture_load` | 7 | `(handle, src, len, format) -> texture_id` | decode IWI and upload | `-EINVAL`, `-ENOSYS` unknown container, `-EIO` decode, `-ENODEV`, `-ENOMEM` (`:462`, `:316`) |
| 8 | `info` | 8 | `(handle, ptr, cap) -> bytes` | 24-byte snapshot: limits, canvas size | `-EINVAL`, `-ENOSPC`, `-ENODEV` (`:465`, `:359`) — `REENTRANT_READONLY` |
| 9 | `screenshot` | 9 | `(handle, ptr, cap) -> bytes` | RGBA8 readback of the last frame | `-EINVAL`, `-ENODEV` nothing presented, `-ENOSPC` short buffer, `-EIO` download (`:466`, `:384`) |
| 10 | `set_texture` | 10 | `(handle, pipe_id, slot, texture_id) -> i32` | bind a texture to one page of a pipeline's array | `-EINVAL` slot/dimension, `-ENOENT` pipe/texture, `-ENOMEM`, `-EIO` (`:464`, `:341`) |

**Only `info` is `TENSION_IMPORT_REENTRANT_READONLY`** (`adapter.cpp:465`). No verb
is `DEFERRABLE`: `submit` could be, and deliberately is not,
because its answer is a count the caller uses to decide whether to split a bucket
and a deferred call cannot answer (`DESIGN.md:128-134` — **[I]**, rationale only;
the code simply registers no flag).

**`submit` is one `guest_read` for the whole array**, not one per record
(`adapter.cpp:266-284`). A 4096-record bucket is one call into the interpreter;
per-record reads would be 4096.

Everything in this section is **[V]**: each row cites the registration line and
the shim, and `tension-core/tests/ogre_surface.rs` has no 2d twin — the verb
surface is pinned by the smoke core instead (§7).

## 3. The window it owns — and the architecture it contradicts

**`tension-2d` creates its own `SDL_Window` today.**

When `open` is called with `TENSION_2D_OPEN_WINDOWED`, the device is created and
then:

```c
impl_->window = SDL_CreateWindow("Tension", width, height,
                                 SDL_WINDOW_RESIZABLE | SDL_WINDOW_HIGH_PIXEL_DENSITY);
```

(`render.cpp:504-506`), followed by `SDL_ClaimWindowForGPUDevice` (`:512`). The
offscreen path — the default, and what every test uses — creates no window at all.

This contradicts the north star. `docs/architecture.md` §1 states that the host
owns the machine and the guest never learns that SDL3 exists; §2's ownership table
assigns `SDL_Window` to the host, created at `platform.rs:352`. With
`--window`, the host opens one window and `tension-2d` opens a second, and the
guest's 2D frame is not drawn into the window the host owns. `docs/architecture.md`
§8 records the same finding from the ownership side.

**It is not a small fix and it is not fixed.** Unifying the two means the 2d
capability consumes the host's `VkSurfaceKHR` the way `tension-ogre` does — which
requires the 2d path to move from SDL_GPU's own swapchain (`SDL_ClaimWindowForGPUDevice`,
`render.cpp:512-521`) to either an external-surface handoff SDL_GPU does not offer
or a second renderer path. Recorded in `docs/known-limitations.md` and in
contradiction 24. **Deferred, with the deferral stated in code:** the header calls
the window "a presentation path, not a second renderer" (`tension_2d.h:72-74`),
which is true of the *pixels* — `present` blits the same target it would have read
back — and does not make the window any less the adapter's.

A guest that uses `--window` with the 2d capability gets two windows. Nothing
warns at run time. That is the honest state.

**[V]** for the code (the `SDL_CreateWindow` call, the claim, the host's own
window); **[I]** for the consequence in a *running* guest, because no test
exercises the windowed path (see §7) — the two-window claim follows from the two
calls, not from an observed run.

## 4. The graph compiler

`tension-2d/DESIGN.md:13-16` says, in its status paragraph: **"What is not built
is §6: the graph compiler. `set_pipeline` accepts the built-in preset by id and
answers `-ENOSYS` for a guest blob."**

The code disagrees, on both halves — and so does the header it describes.

**Shipped graphs.** `scripts/build-2d.mjs` compiles two graphs —
`default_2d` and `default_2d_scaled` — to SPIR-V at build time and embeds them
(`build-2d.mjs:147-150`, `:257-274`). `Renderer::set_pipeline_blob`
(`render.cpp:688-725`) hashes the incoming blob and returns the embedded pipeline
for a hash it was built with; ids 100 and 101 are the shipped graphs
(`build-2d.mjs:150`).

**Runtime graphs.** A blob this build was not built with is `-ENOSYS` from the
renderer (`render.cpp:706-712`), and the adapter then asks the host to compile it
through ABI v5's `compile_graph` slot (`adapter.cpp:187-231`). The core implements
that slot for real — `tension-core/src/adapter/ffi.rs:1039-1080` calls
`tension_core::pipeline::naga_backend::compile`, a module that contains a parser
(`pipeline/parser.rs`), a validator (`pipeline/validate.rs`), a GLSL backend
(`pipeline/glsl_backend.rs`) and a Cranelift comparator
(`pipeline/cranelift_backend.rs`). The resulting SPIR-V goes back through
`Renderer::set_pipeline_spirv` (`render.cpp:736-755`) as a pipe id from 1000 up
(`render.cpp:211`, `:747-749`).

**It is proven end to end.** `scripts/test-2d.mjs:77-91` emits a graph the build
never saw — `default_2d` with the quad at 1.5× — using the core's own
`graph emit-scaled`, and then drives it through the registered import table on a
stub core whose `compile_graph` shells out to the real compiler. DESIGN.md's own
§14.2 has the correct account ("Runtime compiler — built, narrowly"), which makes
§6's status line stale *within the same document*.

**So the correction is threefold:**

1. `DESIGN.md:11-16` ("not built") is false; §6 describes an implemented system
   and §14.2 describes it accurately.
2. The header said the same thing, and its id ranges were wrong too. It has been
   corrected (`tension_2d.h:97-134`, `:335-350`): `PIPE_PRESET_MIN..MAX` is the
   preset band, `PIPE_GUEST_MIN..MAX` is where the build's embedded graphs sit,
   and `PIPE_RAW_MIN` upward is a graph compiled at run time. The header now
   names the constants instead of repeating literals, so a range that moves moves
   in one place.
3. What is genuinely **not** built is `shader_compile_raw` — verb 4 answers
   `-ENOSYS` because the DSO has no GLSL→SPIR-V translator, and the host's
   `compile_graph` takes a graph, not two shader sources (`DESIGN.md:1511`,
   `adapter.cpp:248-255`).

**Bounds on the claim.** The runtime compiler is proven for graphs whose
structure the GLSL backend already lowers; a graph shape it does not know is a
refusal, not a crash. That is DESIGN.md §14.2's "built, narrowly", and this page
adopts it rather than claiming general compilation. The narrowing is **[I]**: no
test enumerates which shapes the GLSL backend refuses, so "a shape it does not
know" is a category with no measured boundary.

## 5. The rendering path

**Open.** `SDL_Init(SDL_INIT_VIDEO)` (`render.cpp:485`) — refcounted process-wide,
and `tension-input` does the same — then `SDL_CreateGPUDevice(SPIRV)`
(`render.cpp:491`), the window and claim if asked (`:504-521`), then the offscreen
target at canvas size (`:525`), then the storage and uniform buffers sized
`kMaxRecords × 28` (`render.cpp:578`, `:588`).

**Submit.** The 12-byte header plus `records_count × record_stride` bytes are read
in one `guest_read`, the stride is checked against the layout, and the records are
appended to the named bucket (`adapter.cpp:257-300`). A bucket holds 4096
(`render.cpp:55`); a short bucket is `-ENOSPC` and the caller splits.

**Present.** Stable-sort each bucket on `(sort_key, group_id, z)`
(`render.cpp:775-777`, key order from `compare_by_keys`, `render.cpp:104-110`),
concatenate the buckets into one frame array, upload once, and draw one call per
bucket with `first_instance` distinguishing them (`render.cpp:757-782`). Sorting
is stable so equal keys keep submission order, which is what makes a frame
reproducible (`render.cpp:772-774`).

**Present to a window.** When a window was claimed, `present` acquires the
swapchain and blits the target into it (`render.cpp:918-953`) — a blit rather than
a second render pass because the target and the swapchain may differ in format.
The readback path is unaffected: `screenshot` still returns the same frame
(`tension_2d.h:72-74`).

**Textures.** `texture_load` decodes IWI (`texture.cpp:59-100`): magic `IWI1`,
74-byte header, interleaved 8-bit RGB/RGBA; planar storage is refused at v1
(`texture.cpp:83`). PNG and JPEG are `-ENOSYS`, not a guess, until ImageViewer
exposes `iw_decode_to_format` (`texture.cpp:20-26`). A texture uploads to a
`SDL_GPUTexture`; `set_texture` copies it into one layer of a pipeline's array
texture of `TENSION_2D_MAX_ATLAS_PAGES` = 16 layers (`tension_2d.h:288-292`), so
every page of a pipeline shares one size and a mismatched page is `-EINVAL`
(`tension_2d.h:207-228`).

**Screenshot.** `SDL_DownloadFromGPUTexture` into RGBA8, top-left origin,
non-premultiplied, always `w × h × 4` bytes regardless of what the driver chose
internally (`tension_2d.h:252-261`, `DESIGN.md:1224-1230`).

All of this is **[V]** except the windowed blit, which is **not yet proven** — it
is the same code path every scenario skips.

## 6. Failure modes

The vocabulary is the adapter ABI's, with the recorded `-ENODEV` exception all
three capability headers carry (`tension_2d.h:327-343`).

- **`-EINVAL`** — the catch-all: a bad handle, `flags` with an unknown bit, a
  canvas outside 1..16384, a non-zero submit header flag, a stride that disagrees
  with the layout, a slot outside 0..15, a texture whose dimensions disagree with
  the array.
- **`-ENOENT`** — a `pipe_id` or `texture_id` this handle never had; a preset id
  outside 1..9 (`adapter.cpp:232-235`).
- **`-ENODEV`** — no GPU device (no driver, no ICD), a window that could not be
  created or claimed, or `screenshot` before anything has been presented. This is
  the code outside the ABI's closed list; the amendment the core owes is one line
  (`tension_2d.h:327-333`).
- **`-ENOSYS`** — a blob with no embedded artifacts and no host compiler, a
  raw-shader compile, a texture container this build does not decode.
- **`-ENOSPC`** — a full bucket, a short guest buffer, a full pipeline table (16).
- **`-EIO`** — SDL refused, shader translation failed, a decode or download failed.
- **`-ENOMEM`** — target, texture or array allocation failed.
- **`-ECANCELED`** — the windowed handle's window was closed. `present` answers
  it once and then draws nothing more (`tension_2d.h:80-83`).

**One refusal the design note asks for and the code does not have.**
`DESIGN.md:1213-1218` says the adapter should refuse `SDL_VIDEODRIVER=dummy` by
name, because `dummy` comes up as a video driver with no GPU backend and fails
`SDL_CreateGPUDevice` with a message that reads as "no GPU". No `dummy` check
exists in `render.cpp` (`rg 'dummy'` returns nothing), so a headless run that sets
`dummy` out of habit gets `-ENODEV` and a message about the device, not the
driver. Recorded as contradiction 25.

The errno table itself is **[V]** (each code is a `refuse()` at the cited shim);
the claim that every path is reachable is **not yet proven** — several refusals,
notably `-EIO` on pipeline creation, need a driver that fails, which this rig's
RADV does not do on demand.

## 7. Tests

**The unit of proof is a stub core, not a unit test.** `scripts/test-2d.mjs`
builds the DSO, compiles `tension-2d/tests/smoke_core.cpp` into a fake
`tension-core` that dlopens the capability and provides `register_import` and
guest memory, and drives every verb **through the registered import table**
(`test-2d.mjs:1-12`). A test that called the shims directly would skip
registration, signature checking and the `ret`-versus-status split — which is
where the interesting bugs live.

What `smoke_core.cpp` (1,293 lines) asserts, per `DESIGN.md` §14.1:

- ten sprites at recorded positions, 10,240 non-black pixels = 10 × 32 × 32;
- reverse-`sort_key` submission is byte-identical to forward submission;
- a parsed graph renders byte-identically to the hand-written preset, and the
  build refuses if their SPIR-V differs;
- a graph the compiler was never taught (`default_2d_scaled`) renders at 2×, and
  its SPIR-V *does* differ from the preset;
- composite grouping: two characters, three layers each, one pixel proves the
  group ordering;
- a second handle at 320×180 reports that size and puts sprites where a 320×180
  projection says; opening at 0, 16385 or a non-zero flag is `-EINVAL`;
- animation by `src_x` alone, with a `TENSION_2D_FREEZE_FRAME=1` revert test;
- multi-atlas: two pages in one draw, page 16 and an unknown pipe refused;
- malformed blobs and invalid graphs are refusals, not panics
  (`pipeline::parser::tests`, `pipeline::validate::tests`).

**Revert-tested** (DESIGN.md §14.1 says so explicitly): the quad arithmetic, the
sort, and the composite keys were each broken on purpose to confirm the assertion
fails.

**In `npm test`:** `test-2d.mjs` itself is not a suite; the 2D path is covered by
`isometric` and `isometric-framework` (`scripts/test.mjs:239-285`), which build
real guests and assert specific pixels, and by `isometric-art`
(`:254-266`), which runs the same scene from generated flat-colour pages.

**Not covered by any test:** the windowed path (`TENSION_2D_OPEN_WINDOWED`).
Every scenario runs `SDL_VIDEODRIVER=offscreen`, so `SDL_CreateWindow`,
`SDL_ClaimWindowForGPUDevice` and the swapchain blit are compiled and unexercised.
This is also why the two-window contradiction in §3 has never been observed in a
test run.

## 8. Non-goals

- **The record layout belongs here, and is here.** There is exactly one record
  shape, 28 bytes, and it is the wire (`tension_2d.h:246-264`); there is no
  separate region or table to describe. The guest SDK's view is
  `tension-framework/assembly/2d/types.ts`.
- **`shader_compile_raw`'s translator** — deferred; the door exists in the wire,
  not in the build (`tension_2d.h:120-128`).
- **Host-owned window / external surface** — deferred, §3.
- **PNG/JPEG decoding** — belongs to ImageViewer's plugin DSOs
  (`texture.cpp:20-26`).
- **Skeletal 2D, per-frame uniforms beyond `parallax_offset`, Android, an
  alternative-backend vtable** — `DESIGN.md:1279-1299`, still accurate.
- **The adapter ABI, the guest import list, the session contract** —
  `docs/abi/adapter.md`, `docs/abi/guest.md`, `docs/session.md`.

**Licence posture, preserved from the design note.** Everything in the 2D path is
permissive: SDL3 (Zlib), glslang (BSD-3, build-time only — it never reaches the
DSO's `DT_NEEDED`), Cranelift (Apache-2.0 with LLVM exception, already transitive
through Wasmtime), ImageViewer (Apache-2.0, not MIT), Tension and TensionScript
(MIT). FreeImage — the one non-permissive dependency — was removed outright, and
`third_party/patches/ogre-no-freeimage-codec.patch` plus the configure flags
(`scripts/bootstrap.mjs:418-419`) are what keep it out. No GPL or LGPL is in the
path. `DESIGN.md:1233-1277` is the long form; `third_party/README.md:84-123`
carries Ogre-Next's half.
